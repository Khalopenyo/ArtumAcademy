# VideoEdit Academy — главный скилл проекта

Это скилл-точка входа. При любой задаче в этом репозитории сначала прочитай это, потом — релевантные подскиллы.

## О проекте

VideoEdit Academy — онлайн-платформа курсов по монтажу видео (рынок РФ и СНГ). Этап: активная разработка MVP, продакшен ещё не запущен.

Что есть в продукте:
- Платные курсы с видеоуроками
- Домашние задания с проверкой куратором
- Сертификаты, прогресс, личный кабинет
- Тарифные планы, оплата через ЮKassa
- Целевая нагрузка MVP — до 10 000 пользователей

Полное ТЗ — в `docs/tz.md` (если положено в репо).

## Семь обязательных правил

Эти правила приоритетнее любых задач. Если задача нарушает — остановись и спроси.

1. **Никогда не пиши значения секретов в код.** Только переменные окружения. `.env.local` в gitignore. В `.env.example` — только имена с описаниями.
2. **Никогда не используй `service_role` ключ Supabase в клиентском коде.** Только в Server Actions, Route Handlers, Edge Functions.
3. **Никогда не отключай RLS** на публичных таблицах БД. Если для задачи нужен обход — используй service_role на сервере, не выключай политики.
4. **Никогда не пушь напрямую в `main`.** Только через ветки `feat/...`, `fix/...`, `hotfix/...` и PR.
5. **Никогда не доверяй ценам и правам с клиента.** Цены тарифов берутся из БД по id. Роли проверяются на сервере.
6. **Никогда не используй `any` и `// @ts-ignore`** без обоснования и привязки к тикету. Используй `unknown` + type guards.
7. **Никогда не пиши деструктивные операции** (`DROP TABLE/COLUMN`, `TRUNCATE`, `DELETE` без WHERE) без явного "да, делай" от пользователя.

## Цикл работы над любой задачей

```
ПОНЯТЬ → УТОЧНИТЬ → СПЛАНИРОВАТЬ → СОГЛАСОВАТЬ → СДЕЛАТЬ → ПРОВЕРИТЬ → ЗАКОММИТИТЬ
```

Подробности — в подскилле `workflow`. Пропускать этапы можно только для тривиальных правок.

## Структура репозитория

```
.
├── .claude/skills/              ← скиллы проекта (этот файл и подскиллы)
├── docs/                        ← дополнительные документы (tz.md и пр.)
├── src/
│   ├── app/                     ← Next.js App Router
│   │   ├── (marketing)/         ← публичный лендинг
│   │   ├── (app)/               ← личный кабинет (под auth)
│   │   ├── (admin)/             ← админ-панель (под role-check)
│   │   ├── api/                 ← Route Handlers (вебхуки, OAuth)
│   │   └── layout.tsx
│   ├── components/
│   │   ├── ui/                  ← примитивы shadcn/ui
│   │   ├── marketing/, lessons/, admin/, shared/
│   ├── lib/                     ← клиенты Supabase, обёртки внешних API
│   ├── hooks/, stores/, types/
│   └── server/
│       ├── actions/             ← Server Actions
│       └── queries/             ← серверные запросы
├── supabase/
│   ├── migrations/              ← SQL-миграции (только вперёд)
│   └── seed.sql
├── tests/
│   ├── unit/                    ← Vitest
│   └── e2e/                     ← Playwright
└── package.json
```

Имена файлов:
- React-компоненты: `PascalCase.tsx`
- Утилиты и хуки: `camelCase.ts`
- Миграции: `YYYYMMDDHHMMSS_short_description.sql`
- Тесты: `Foo.test.ts` рядом с исходником

## Когда подгружать другие скиллы

| Задача | Подскилл |
|---|---|
| Делаешь компонент, страницу, форму | `ui-conventions` |
| Трогаешь БД, пишешь миграцию | `database` |
| Server Action, Route Handler, webhook | `api-conventions` |
| Авторизация, RLS, секреты, платежи | `security` |
| Пишешь тесты | `testing` |
| Не понимаешь как двигаться по задаче | `workflow` |

Эти подскиллы лежат в `.claude/skills/` рядом с этим файлом. Активируются автоматически по релевантности задачи, но если не уверен — прочитай вручную через инструмент Read.

## Финальное правило

Если не уверен — **спроси, а не угадывай**. В этом проекте основной автор кода — Claude. Некому будет указать на неверное направление в код-ревью.
