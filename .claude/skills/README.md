# VideoEdit Academy — пакет Skills для Claude / Claude Code

Это набор Skills для Claude. Каждый скилл — папка с `SKILL.md`, описывающим конкретную область знаний и правил проекта.

## Что такое Skill

Skill — это формат расширения Claude. Состоит из:
- `SKILL.md` с фронтматтером (`name`, `description`)
- опционально — другие файлы (scripts, docs, шаблоны)

Claude **сначала читает только `description`** всех доступных скиллов. Если задача попадает под description, он **подгружает содержимое** SKILL.md и работает по этим правилам.

Это даёт три преимущества перед обычным `CLAUDE.md`:

1. **Экономия контекста** — детальные правила загружаются только когда нужны
2. **Композиция** — несколько скиллов могут активироваться одновременно
3. **Переиспользуемость** — один скилл можно использовать в нескольких проектах

## Что внутри пакета

```
skills/
├── videoedit-academy/SKILL.md   ← мастер-скилл, точка входа
├── workflow/SKILL.md             ← цикл работы над задачами
├── database/SKILL.md             ← миграции, RLS, запросы
├── api-conventions/SKILL.md      ← Server Actions, Route Handlers
├── ui-conventions/SKILL.md       ← React-компоненты, Tailwind, формы
├── security/SKILL.md             ← секреты, auth, защита данных
└── testing/SKILL.md              ← unit / integration / E2E
```

**`videoedit-academy`** — главный, содержит общий обзор, стек, обязательные правила и указания, какой подскилл когда нужен. Активируется на любую задачу в проекте.

**Подскиллы** активируются по релевантности задачи.

## Куда положить скиллы

### Вариант A — Claude Code в репозитории (рекомендуется)

Положи скиллы прямо в репо проекта:

```bash
# В корне репо
mkdir -p .claude/skills
cp -r skills/* .claude/skills/
```

Теперь когда любой разработчик (или Claude Code) клонирует репо и запускает Claude Code — скиллы автоматически становятся доступны.

Добавь в `.gitignore` только если хочешь приватные правила, иначе закоммить:

```bash
git add .claude/skills
git commit -m "chore: add project skills for Claude"
```

### Вариант B — личные скиллы (всегда доступны)

Если хочешь, чтобы скиллы были у тебя на любом проекте:

```bash
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/
```

Эти скиллы будут активироваться независимо от проекта. Удобно для общих вещей вроде `workflow`, но `videoedit-academy` со специфичным стеком лучше держать в самом репо.

### Вариант C — claude.ai (веб-интерфейс)

В claude.ai зайди в **Settings → Capabilities → Skills** и загрузи каждый скилл папкой (либо zip). После этого скиллы будут доступны во всех чатах.

Используй этот вариант когда хочешь обсуждать архитектуру или планировать задачи в чате, а не в Claude Code.

## Как проверить, что работает

### В Claude Code

После установки запусти Claude Code в репо и напиши:

> Покажи список доступных скиллов и их описания.

Claude должен перечислить `videoedit-academy` и подскиллы. Если их нет — проверь путь установки и фронтматтер в SKILL.md (обязательны поля `name` и `description`).

### Тестовая активация

> Создай Server Action для создания нового курса.

Claude должен:
1. Сам подтянуть `api-conventions` (по слову "Server Action")
2. Может подтянуть `database` (если нужна миграция)
3. Следовать правилам из этих скиллов

Если он начинает писать код в стиле, который противоречит правилам — скиллы не активировались.

## Как поддерживать

Скиллы — это **живая документация**. Обновляй когда:
- Меняется стек (добавилась библиотека, переключились на другой сервис)
- Появился новый паттерн, который хочешь закрепить
- Что-то сломалось из-за того, что Claude не знал правила — добавь правило в соответствующий скилл

Меняй прямо в `.claude/skills/<name>/SKILL.md`, коммить как обычный код.

## Чего НЕ должно быть в скиллах

- **Секретов, ключей, паролей** — это `.env.local`, не скиллы
- **Личных предпочтений** ("я люблю табы вместо пробелов") — это `.editorconfig` и Prettier
- **Длинного ТЗ** — положи отдельно в `docs/tz.md` и сошлись из мастер-скилла
- **"Ты опытный разработчик который..."** — не персона, а правила. Claude и так старается. В скиллах должна быть **проектная специфика**.

## Что важно знать про "Get Shit Done" подход

Эти скиллы написаны в духе "не философствуем, делаем":
- Каждое правило — конкретное, проверяемое
- Каждый паттерн с примером кода, не абстрактным описанием
- Каждый запрет с альтернативой ("не делай X, делай Y")

Если правило не выполняет одно из этих условий — оно мусор и должно быть переписано или удалено.

## Связь с ТЗ

Полное техническое задание в `ТЗ_VideoEdit_Academy.docx`. Если хочешь, чтобы Claude его читал — конвертируй в Markdown и положи в `docs/tz.md`. Мастер-скилл `videoedit-academy` уже ссылается на этот путь.
